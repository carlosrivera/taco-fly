¿Dónde comería una mosca en CDMX?

Working title: Taco Fly / Mosca Maps / Drosophila Maps
Version: 0.1
Status: Prototype
Target: Viral interactive web experiment
Core premise: Connect a fruit fly inspired neural controller to a map of Mexico City and let it navigate a simulated olfactory landscape generated by real taquerías.

1. The one sentence version

We put a fruit fly brain on a map of Mexico City’s taquerías, give every taquería a simulated smell, and let the fly decide where to eat.

The user opens the site, sees CDMX covered in taquerías, presses:

RELEASE FLY 🪰

The fly begins navigating the city in real time.

It receives no route and does not know where the restaurants are. It only receives simulated sensory information derived from the environment around its current position.

The eventual ambition is to drive those decisions using connectivity from the MaleCNS fruit fly connectome.

2. Why this exists

Recent fruit fly connectome projects have demonstrated that biological neural connectivity can be incorporated into simulations and embodied environments.

Most demonstrations are framed around conventional tasks such as locomotion, robotics or videogames.

This experiment asks a much more important scientific question:

Where would a fruit fly eat tacos in Mexico City?

The project should live somewhere between computational neuroscience, generative art, simulation and an extremely unnecessary use of engineering resources.

It should be understandable without understanding any of those things.

The first five seconds matter more than the technical explanation.

3. Desired reaction

The experience should create three sequential reactions.

0 to 3 seconds

Wait, what?

The user sees a map of Mexico City, hundreds of taquerías and a fruit fly.

3 to 15 seconds

Holy shit, it’s actually moving.

The fly starts navigating and leaving a trail through the city.

15 to 60 seconds

How the fuck does this work?

Only then do we explain the connectome, sensory simulation and limitations.

The project fails if understanding it requires reading the explanation first.

4. Primary experience

The landing page immediately displays an interactive map centered on CDMX.

Taquerías appear as points across the city.

A fly waits somewhere on the map.

Large primary action:

RELEASE FLY 🪰

Once released, the simulation begins.

The camera loosely follows the fly while still allowing the user to pan and zoom.

Its path appears behind it.

Nearby taquerías generate visible olfactory fields.

The fly responds continuously to those fields and changes direction.

When it reaches a taquería, the event is recorded.

Example:

🪰 Taquería discovered
El Vilsito
01:47:32 into simulation

The simulation continues.

There is no destination.

There is no predefined route.

7. The smell model

Every taquería emits a virtual odor field.

Simplest model:

S(d) = I × exp(−k × d)

Where:

S = perceived smell intensity

I = source intensity

d = distance from the taquería

k = decay coefficient

The fly does not receive restaurant coordinates.

At any moment it receives sensory information representing the surrounding smell landscape.

V0 sensory vector might contain:

smell_left
smell_forward
smell_right
total_smell
smell_gradient

This deliberately simplifies biological olfaction.

The important property is that the fly discovers restaurants through local environmental signals rather than global map knowledge.

8. Wind

Wind is the first major environmental modifier.

Without wind, smell fields are approximately radial.

With wind, they become directional.

Conceptually:

        wind →
        🌮
       ╱  ╲
      ╱    ╲
           ╲
            ╲═══════>

V0 may use simulated constant wind.

V1 can incorporate actual CDMX wind conditions.

Wind should dramatically alter the fly’s route.

This creates a reason to rerun the simulation.

9. Fly controller

The controller receives sensory information and produces:

forward velocity
angular velocity

Nothing else is required initially.

Interface:

Environment
     ↓
Sensory encoder
     ↓
Fly controller
     ↓
Motor decoder
     ↓
Environment

This interface must remain constant regardless of the controller implementation.

That lets us swap controllers without rebuilding the world.

10. Controller stages

Controller A: Dumb Fly

Used exclusively to validate the experience.

A simple probabilistic chemotaxis algorithm.

Example behavior:

Move forward.

Introduce random heading variation.

Increase probability of turning toward stronger odor gradients.

Avoid oscillation.

This gets the visual experience working immediately.

It should never be presented publicly as MaleCNS.

Controller B: Neural Fly

Replace the procedural controller with a neural dynamical system.

The topology should derive from MaleCNS connectivity where practical.

Initial implementation can use simplified neuron dynamics rather than full biological simulation.

Example:

aᵢ(t+1) = f(Σ wⱼᵢ aⱼ(t) + Iᵢ(t) − λaᵢ(t))

Sensory inputs stimulate selected sensory populations.

Activity propagates through the network.

Selected motor populations determine movement.

Controller C: Connectome Fly

Long term objective.

Use biologically justified sensory populations, connectivity and motor populations derived from MaleCNS annotations and supporting literature.

At this stage we should be able to describe precisely which parts of the behavior originate from the connectome and which are abstractions introduced by us.

11. Absolutely no LLM in the control loop

An LLM may explain the experiment or generate humorous commentary.

It must not determine:

Where the fly moves.

Which taquería it selects.

What sensory input matters.

Whether a behavior counts as successful.

Otherwise the central premise becomes misleading.

12. Simulation state

Each fly maintains:

{
  "position": {},
  "heading": 0,
  "velocity": 0,
  "energy": 1,
  "age": 0,
  "controllerState": {},
  "visited": []

Every simulation should have a deterministic seed where technically possible.

Runs should be reproducible.

15. The trail

The path is arguably the most important visual artifact.

The fly continuously leaves a line showing its trajectory.

Visited taquerías remain highlighted.

The full route should eventually look like an insane biological traveling salesman solution drawn over CDMX.

Users should be able to hide the map and view only:

The shape created by a fruit fly navigating Mexico City’s taco smell landscape.

That image should be exportable.

16. Comparison mode

Later versions can run several controllers against identical environmental conditions.

Example:

FRUIT FLY       38 taquerías
RANDOM WALK     17 taquerías
GREEDY          52 taquerías
TSP             81 taquerías

Metrics should include distance, restaurants discovered, energy efficiency and exploration.

This is not about claiming the fly is the optimal routing algorithm.

It is about showing how differently biological wiring navigates the same environment.

18. Live mode

Long running simulations should continue server side.

The homepage can therefore feature:

Instead of every visitor starting from scratch, they can watch a fly that has been navigating CDMX for hours or days.

This gives the project continuity and creates material for follow up posts.

21. V0 success criteria

The video should show:

Taquerías.

Smell field.

Fly changing direction.

25. Product principle

Whenever choosing between scientific complexity and something visible, choose visible first.

Whenever choosing between fake intelligence and a simpler honest simulation, choose the simpler simulation.

Whenever behavior looks interesting, preserve the run before changing anything.

The entire project depends on one thing:

We don’t decide where the fly goes.
